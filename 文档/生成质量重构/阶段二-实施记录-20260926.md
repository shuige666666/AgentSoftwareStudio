# 阶段二实施记录（2026-09-26）

本记录对应[阶段二：单 Agent 的实现、验证与修复](./03-实施路线与效果验证.md#section-2-3)。设计约定仍以《02-目标架构与设计约定》为准。下面区分已实现能力、自动测试与真实模型样本；单次 smoke 不代表稳定质量收益。

## 已实现

主链在规划、脚手架及既有计划产物后，启动一个 `DEVELOPMENT` 工作区会话。该会话可以改生产代码、前端、开发测试与 README，并从同一磁盘工作区读取、执行和修复。旧前端评审、测试生成和外层修复服务不再接在该会话之后；会话达到上限或异常停止时，平台保留候选并执行一次最终独立验收。

`apply_patch` 对多文件新增、修改、删除做落盘前预检，返回实际写入文件及失败路径；支持 `*** Begin Patch` 与标准 unified diff。`bash` 使用固定镜像的持久 Docker 容器，断网、非 root、只读根文件系统和 Maven 仓库、只读平台元数据挂载，并限定内存、进程、路径与超时。Bash 修改磁盘后更新会话写入版本；正式验证前关闭容器，避免后台进程继续写候选。脚手架 root 容器留下的 `target/` 会在开发 Shell 启动前清理，使非 root Shell 可自行运行 Maven。上下文按保守 token 估算阈值压缩，保留原始目标和最近完整的 assistant/tool 配对。

`submit_checkpoint(scope=progress)` 冻结源码和配置到独立副本，在该版本上编译和运行全量已有测试；`scope=final` 再做项目契约门禁，只有通过才结束开发会话。结果关联源码 SHA-256、快照、日志和结构化报告；环境错误记为 `BLOCKED`，编译、测试或契约失败记为 `FAILED`。`report_blocker(kind=planning_conflict)` 会让 PlanningAgent 复核，必要时修订有效设计与契约，并把决定返回原会话。平台根据真实验证记录生成 `.software-studio/delivery-report.md`；README 由开发会话维护。

当 `progress` 已通过且源码与配置哈希在 `final` 时完全相同，`final` 复用前一次完整编译与测试结果，只重新执行契约门禁；新报告明确标记 `reusedVerification` 并复制先前的完整日志。文件版本发生变化则重新编译和运行全量测试。此优化在两个真实 smoke 之后加入，已由针对性测试验证；下面的真实耗时仍是优化前实测值。

基准报告现记录实际开发会话的轮次、工具上限和验证协议。旧外层修复预算不再作为本阶段运行参数记录。用户调整的 `AiConfig.java` 模型别名保持原样，本次没有修改。

## 自动验证

本地 `mvn -q test` 覆盖新协议与原有功能；另显式运行真实 Docker Shell 测试，检查非 root 身份、平台元数据只读、`/workspace` 工作目录映射、脚手架构建产物清理以及容器内 Maven 编译。针对性测试覆盖多文件补丁与 unified diff、新增文件、预检失败、测试发现生产缺陷后同一会话修复、progress 不提前完成、final 失败与通过、规划冲突结果回传、旧会话不再参与主链、独立快照及基准失败报告保留。

补齐依赖和隔离收尾后，正式 checkpoint 保留原始源码快照，另建执行副本运行 Maven，防止测试自行写文件改变已记录的受检版本。编译、测试均改用断网、非 root、只读 Maven 缓存的容器，不再借用旧验证容器的个人仓库可写挂载。离线输出明确显示缓存缺项时，平台使用固定 Maven Central 镜像设置，在执行副本只读、无个人配置和凭据的独立容器中运行依赖预取，随后回到断网容器重试原命令；预取日志写入 checkpoint，仓库连接故障标记环境阻断。普通编译错误不触发预取。原生 Java 项目的正式命令也走隔离容器。

最终 `mvn -q test` 通过。常规全套执行后的 Surefire 报告共 50 个套件、193 项测试，0 失败、0 错误、5 项跳过（包含默认关闭的真实 Docker 检查）。显式启用的 Docker Shell 测试 2 项通过；另显式启用的 Maven 预取测试通过：带生产和测试依赖的样例预取后，在断网容器中完成编译与 1 项 JUnit 测试。`git diff --check` 通过。

## 真实模型诊断样本

固定短链案例 `url-shortener-behavior-v1` 的首次 smoke 使用 `qwen3.7-flash` 别名编码、`qwen3.7-max-2026-05-20` 规划。模型首次提交标准 unified diff 被旧解析器拒绝，之后改用逐文件 Bash 写入并在第 36 轮触及上限。平台对保留候选的最终独立快照编译及 12 项测试通过，外部 HTTP 的 5 项行为通过；报告为 `benchmark-results/benchmark-2026-09-26T03-42-32.147118700Z.json`。这验证了候选保留和最终兜底验收，但不能证明连续开发反馈效率。

第二次同案例启用 unified diff 后，首次补丁成功落盘 14 个文件；模型使用 `/workspace` 作为 Bash 工作目录而被旧路径规则拒绝，重复错误触发停滞。保留候选的测试编译失败；报告为 `benchmark-results/benchmark-2026-09-26T03-52-10.065492Z.json`。随后已支持该工作目录并增加真实容器测试。

第三次同案例中，模型以 `-0,0` hunk 表示新增文件但仍填写普通 `a/` 路径，旧解析器误判为修改不存在的文件；已据此扩展解析并加入回归测试。模型转向 Bash 后暴露脚手架 `target/` 的 root 权限冲突，修复前在第 36 轮停止。该候选最终快照编译和 9 项测试通过，但静态契约门禁发现 `GET /{code}` 未匹配；基准 HTTP 请求返回 500，未形成完整报告。已补强失败路径的外部判卷异常处理；此轮不能计为行为通过。

第四次同案例在上述修复全部生效后，第 3 轮首次 `apply_patch` 一次写入 13 个文件；非 root Bash 在候选工作区成功执行 Maven 编译和测试。第 8 轮 `progress` 与第 9 轮 `final` 均在独立快照通过，项目内 8 项测试通过，外部 HTTP 的 5 项行为通过。共 11 次模型调用，耗时 221672 ms；报告为 `benchmark-results/benchmark-2026-09-26T04-07-32.590266200Z.json`，产物为 `ai_generated_projects/short-link-service_20260926_120747`。该次第二个补丁请求未应用，但没有影响随后的正式验证；不能把一次通过外推为稳定成功率。

固定投票案例 `poll-system-behavior-v1` 在同一执行链中，首次补丁写入 11 个文件，第二次补丁补充 1 个文件。模型运行 Maven 后发现生成测试调用了当前 AssertJ 不支持的 `isOneOf`，在原会话内修改测试并重新验证；第 15 轮 `final` 通过。项目内 15 项测试与外部 HTTP 的 8 项行为全部通过，共 17 次模型调用，耗时 265794 ms；报告为 `benchmark-results/benchmark-2026-09-26T07-24-41.952690800Z.json`，产物为 `ai_generated_projects/online-voting-system_20260926_152458`。本轮两个后续补丁因上下文或格式问题未应用，Agent 改用 Bash 完成修正；随后已补充新增文件中省略 `+` 前缀的兼容解析及测试。

这两个样本的首次 patch 成功率为 2/2，完整行为通过为 2/2。短链同一源码的 progress 与 final 在优化前各重复一次全量构建和测试：前者编译 6002 ms、测试 16569 ms，后者编译 5778 ms、测试 16519 ms；这直接推动了前述同哈希复用。百炼账单只有日粒度，本次单任务人民币费用仍未知；token 总量不能当作实际扣费。两个案例都只运行了一次有效版本 smoke，模型滚动别名、规划输出变化和样本波动使这些数字不能用于宣称稳定提效。

人工查看这两份通过产物，仍发现固定判卷未覆盖的源码风险：短链 `CodeGenerator` 从 UUID 字符串取 8 位，`LinkService` 保存前未检测碰撞，仓库 `put` 可覆盖旧链接；投票 `PollService.castVote` 先 `hasVoted` 再 `addVote`，并发同一 `voterId` 仍可能重复计票。这些是生成代码质量问题，不能因为本次顺序 HTTP 判卷通过就视为已解决；后续应在版本化案例或额外测试中覆盖，保持既有基准口径可比。

与阶段一结束时的单次样本相比，短链仍为 5/5、投票仍为 8/8，阶段二没有表现出额外的行为覆盖收益；模型调用分别从 27、30 次降到 11、17 次，总 token 从 183717、293693 降到 94179、208723，耗时从 642943、752490 ms 降到 221672、265794 ms。这只是两组非配对运行的开销观察，不等于稳定提效或人民币成本下降。更早的重构前报告中短链为 2/3、投票为 2/8，但短链当时的判卷条目数与当前不同，且模型、流程与时间条件没有严格固定，不能据此把质量差异归因给阶段二。人工对照阶段一产物，短链未处理保存时的短码碰撞，投票也是先查再写且使用未同步的投票列表；阶段二产物仍存在同类边界风险，因此源码质量尚无充分证据优于阶段一。

## 限制与后续验收

验证快照只保证本次受检版本一致，不提供回滚或中断恢复；后者仍属阶段三。Bash 的局部命令用于诊断，正式通过只认独立快照的全量构建、测试与最终契约。外部行为判卷可能发现静态契约和项目测试未覆盖的问题。真实模型样本数量仍不足以判断稳定通过率和费用收益；实际人民币费用保留未知。本次依赖与隔离收尾使用单元测试和真实 Docker 测试，没有追加模型生成样本；待阶段三形成明确可比的候选后再按同一案例版本、模型、预算与环境做配对验证。
