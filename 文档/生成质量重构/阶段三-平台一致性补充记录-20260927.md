# 阶段三平台一致性补充记录（2026-09-27）

## 本轮改动

依据 2026-09-27 对 `43b97e2` 及博客运行轨迹的复核，先处理平台可以确定复现的三处问题，再做固定规划的小范围对照。本记录补充阶段三实施记录，不改变原设计文档的目标或验收口径。

1. 开发会话压缩时，依据持久化的当前里程碑状态重新生成任务说明，包含当前任务、验收条件、当前契约、已接受任务及源码哈希。初次开发与压缩后的说明共用同一生成器。固定消息序列测试覆盖首任务接受、第二任务交接消息移出最近上下文、再次压缩的情况；压缩后仍指向第二任务。
2. 切片规划检查完整契约中每个公开接口是否恰好归入一个任务，页面和前端调用是否保留。归属无法可靠确定时退回完整项目任务。动作识别不再依据接口描述中的 `result/results` 推断结果接口；服务端模板的交互按目标接口分配。业务里程碑只有在页面能由返回模板的接口明确归属时才拆分，否则保留较粗任务。已保存博客规划经新规则重建后，8 个公开接口均被覆盖，形成文章创建与列表、详情、修改动作、评论提交 4 个任务；编辑页随修改动作交付。
3. 最终语义契约结果增加“是否实际执行”状态。若构建或测试失败导致最终契约检查跳过，基准报告显示 `Final semantic contract gates were not executed.`，不能再显示通过。

本地 `mvn -q test`：54 个测试套件，226 项测试，0 失败、0 错误、5 跳过。新增测试覆盖压缩后任务连续性、切片契约覆盖与保守退回、模板归属、契约未执行的报告语义，以及固定规划的两种开发模式。

## 后续故障定位与修复

连续开发补跑的第 3 轮 `apply_patch` 参数长 30740 字符，原始内容无法解析为 JSON；工具正确返回 `TOOL_ARGUMENTS_INVALID_JSON`。第 4 轮请求仍把该非法参数原样作为历史 `function.arguments` 发给百炼兼容接口，服务端因此返回 HTTP 400。现仅在构造模型请求时把非法的历史参数序列化为 `{}`，保留工具调用 ID、工具错误结果及本地审计中的原始参数。定向测试验证失败历史可回放、正常参数不变。另用 `qwen3.7-flash` 做一次 315 输入 token 的真实兼容接口请求：历史 `tool_calls` 使用修正后的 `{}`，仍带原工具失败响应；服务端返回 `stop` 和 `OK`，未再报 HTTP 400。这是协议微型验收，尚不等于完整生成效果验证。

首次连续开发样本的第 31 次调用达到 240 秒请求超时；日志没有证据表明请求参数或平台状态损坏，因此仍记录为远程调用故障，不把它归入上述确定性的 JSON 协议修复。开发工具会话现在只对这种超时在剩余全局模型轮次内原样重试一次；失败尝试计入轮次和模型调用统计，连续第二次超时即停止，不重试其他 HTTP 或运行错误。里程碑样本最终编辑页使用 `#fields.errors`，却没有提供对应的 Thymeleaf 表单绑定上下文，导致 2 项渲染测试报错；这是生成候选源码缺陷，现有最终验证已检出，尚无证据支持为博客模板添加平台专用改写规则。

上述修复后再次运行 `mvn -q test`：54 个测试套件，229 项测试，0 失败、0 错误、5 跳过；`git diff --check` 无空白错误。尚未用完整博客生成检验质量收益。
