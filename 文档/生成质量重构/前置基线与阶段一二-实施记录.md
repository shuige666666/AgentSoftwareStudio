## 阶段状态

前置基线、阶段一和阶段二的实现与链路验证已完成，可以作为阶段三的起点。真实样本仍少，不能由这些交付推断稳定的生成质量或成本收益；阶段三的效果验收尚未通过。

## 前置基线：建立可信判卷

新增显式选择的短链接、投票新版案例，在需求中固定 HTTP 路径、字段、状态码和投票身份。平台在独立 Docker 容器中进行外部 HTTP 判卷，区分通过、失败、未运行和环境异常；报告关联需求、代码版本及停止原因，异常时保留候选和用量。百炼缓存命中及 token 按实际模型统计，同时修复回滚清空不可修改文件列表的异常。

固定产物复判可重复：曾有投票产物通过 8 项检查，短链产物则暴露字段不符合契约。后续完整短链 smoke 虽构建、自测通过，仍未通过外部判卷；补跑投票 smoke 也因平台契约阻断和投票请求失败未通过。这证明了独立判卷的必要性，不是生成质量提升。

## 阶段一：准确规划与可构建起点

主链合并为 PlanningAgent 的需求、总体设计两步，修正 system/user 消息、原始请求传递及嵌套输出约定；关键字段缺失明确反馈，不再静默生成 `GET /`。规划资料在编码前保存。Spring Boot 工作区由平台生成固定 Java 17 骨架及必要依赖，并在业务编码前完成真实编译。

角色、规划字段、脚手架和工作流测试通过。短链接与投票各一次完整 smoke 均通过平台验收和独立 HTTP 检查。脚手架当时只覆盖 `SPRING_BOOT` Profile；骨架可构建与业务正确是分别验证的结果。

## 阶段二：同一会话实现、验证和修复

主链使用单个 DEVELOPMENT 会话完成生产代码、页面、开发测试和修复。补齐多文件 patch 与 unified diff、持久 Docker Shell、上下文压缩及规划冲突反馈。正式 checkpoint 在独立冻结副本上验证并关联源码版本；停止时保留候选并进行最终复核，同版本的 progress/final 可复用编译测试结果。

开发与正式验证采用非 root、断网、只读元数据和依赖缓存；仅明确的离线依赖缺项触发受控预取。平台测试及真实 Docker Shell、Maven 预取验证通过。此前短链诊断运行暴露补丁新增文件、工作目录和构建产物权限问题，修复后同一有效版本的短链、投票各一次完整 smoke 通过；投票还实际走通了测试失败后在原会话修复。

## 保留的限制与交接

人工源码检查仍发现短码保存缺少碰撞处理、投票先查再写可能造成并发重复计票；两阶段通过的顺序 HTTP 检查没有覆盖这些风险，不能记为已解决。快照验证保证受检版本一致，回滚和中断续接由阶段三补充。

单次任务人民币费用未知。用户曾从日粒度账单观察到此前调用合计约 1.69 元，该金额不能分配到单个案例，也不能作为后续调用费用。质量比较继续使用相同案例版本、模型、全局预算和独立验收；后续入口见[阶段三调整计划](阶段三-1-调整与验证计划-20260930.md)。
