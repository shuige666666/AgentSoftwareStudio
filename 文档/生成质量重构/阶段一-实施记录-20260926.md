# 阶段一实施记录（2026-09-26）

本记录对应[阶段一：准确规划输出与确定性脚手架](./03-实施路线与效果验证.md#section-2-2)。设计约定仍以《02-目标架构与设计约定》为准；这里记录实际改动和验证，不把单次 smoke 当作稳定质量收益。

## 已实现

- `AbstractJsonAgent` 经 `LangGraphPromptExecutor` 发送真实的 system/user 消息。规划需求和设计两步均携带原始用户请求；设计 Prompt 明列嵌套结构、契约字段与行为对应。JSON 解析失败保留一次格式修复，关键规划字段缺失时向对应步骤定向重试一次并在仍缺失时明确失败。
- 新主链使用 `PlanningAgent` 的需求摘要与总体设计两步。旧产品经理、架构和契约 Agent 及其 Node 已无运行调用并移除。`ApiEndpointContract` 与 `FrontendCallContract` 缺少 method/path 时保留空值，不再静默形成 `GET /`。需求摘要增加业务规则、假设和待解决问题；总体设计记录领域设计、公开接口的字段与错误语义、必需行为对应。
- 沿用 `.software-studio` 元数据目录，导出原始请求、需求、总体设计、契约和便于阅读的 `planning-overview.md`。规划产物在进入业务编码前保存。
- `ProjectScaffoldService` 对新建的 Spring Boot 工作区使用固定 Java 17 / Spring Boot 3.2.4 模板，生成 POM、入口类、配置、`.gitignore` 和最小上下文测试；业务编码前在 Docker 中执行真实 `mvn -DskipTests compile`，将规格和构建结果保存到项目元数据。已有 POM 的工作区不会被整模板覆盖。短链首次业务编译暴露常用 `@Valid` 所需依赖后，模板加入 `spring-boot-starter-validation`。
- 开发任务仍接收原始请求与有效规划，从现有脚手架开始工作；阶段二才调整开发、测试和修复的独立会话与工具协议。

## 实际验证

`mvn -q test`：45 个测试套件，176 个测试，0 失败、0 错误、2 个跳过。针对性测试验证角色消息、需求原文传递、行为对应、缺失字段反馈、脚手架文件与编译调用、工作流接线及报告字段。`git diff --check` 通过。

真实模型配置为 `qwen3.7-max-2026-05-20`（规划）与 `qwen3.7-flash-2026-07-15`（编码）。短链与投票两例的两步规划均有成功响应，且在第一次业务编码前分别完成了真实脚手架编译：短链用时 5753 ms，投票用时 5793 ms；证据见各项目的 `.software-studio/scaffold-build.json`。这两个结果只证明最小骨架可构建，不能证明启动测试或业务行为通过。

短链完整 smoke 记录在 `benchmark-results/benchmark-2026-09-26T02-39-51.041804Z.json`，产物为 `ai_generated_projects/short-link-service_20260926_104006`。平台构建和测试通过，独立 HTTP 判卷 5 项行为全部通过，完整工作流成功率为 1/1。该次共有 27 次模型调用，Flash 发生 1 次超时；其余 26 次调用成功。超时不能作为模型下架证据。

投票完整 smoke 记录在 `benchmark-results/benchmark-2026-09-26T02-51-29.651295Z.json`，产物为 `ai_generated_projects/online-voting-system_20260926_105153`。平台构建和 15 个项目内测试通过，独立 HTTP 判卷 8 项行为全部通过，完整工作流成功率为 1/1。该次 30 次模型调用均成功；其中部分 Flash 响应接近 240 秒，运行耗时约 12 分 32 秒。两个报告各记录了其启动时的 Git 提交和脏工作区指纹；运行期间的后续局部代码整理没有被这些报告覆盖，最终代码另用本地测试验证。

对两份生成源码做了针对性人工检查，未把行为测试通过升级为整体源码质量结论。短链 `CodeGenerator` 仅从 4 位片段取字符，`LinkService` 保存时也没有碰撞重试，`InMemoryLinkRepository.save` 的覆盖写入可能使旧链接丢失。投票 `PollService.castVote` 的“查询已投票—加入投票”操作作用于 `Poll` 中的普通 `ArrayList`，并发重复请求可能都通过检查；顺序执行的本次行为判卷没有覆盖此情形。这些是后续生成质量改进与回归用例的候选，不计作本次已验证失败。

## 限制和下一步

当前本地脚手架仅覆盖 `SPRING_BOOT` Profile；其他工程类型仍沿用原有生成路径。两个案例各一次 smoke 只能确认主链接入、两个骨架入口和本次固定行为判卷，不足以证明重构后的稳定行为通过率、整体源码质量或成本改善。单次任务人民币费用仍未知，应以人工账单或明确版本化单价假设另行核对，不能由 token 数直接认定实际扣费。

下一阶段按既定设计改造持续开发会话、patch、容器 Shell、上下文和可信验证反馈；阶段一产物作为同模型对照的起点，后续比较仍需多次样本和源码审查。
