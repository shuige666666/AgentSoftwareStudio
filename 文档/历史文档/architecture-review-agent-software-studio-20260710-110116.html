Problem

反馈推迟到全项目末尾，错误跨多个 shallow module 扩散。

Solution

一个 Interface 完成切片生成、落盘、验证与接受；内部保留生成和测试 Seam。

Wins
  • Locality：缺陷停在切片
  • Leverage：一个 Interface 验收
  • 测试命中真实 Interface

深化验证与失败分流 Module

Strongports & adapters

VerificationNodeService · EvaluationNodeService · ProjectRepairService · DockerSandboxService · SoftwareStudioWorkflowData

Before

String logs
↓ contains("BUILD SUCCESS")
String classifier
↓ all failures
One Debugger prompt
Interface = log formats + magic phrases + retry ordering

After

Deep Verification Module
verify(workspace, acceptance) → VerificationResult
implementationtestcontractarchitectureenvironmentevidence

Docker 与本地执行是两个 Adapter，Seam 因真实变化而成立。

Problem

日志文本、成功判断、错误分类和修复路由泄漏到多个 Module。

Solution

结构化 VerificationResult；Failure Triage 根据 failure kind 路由到正确阶段。

Wins
  • Interface 不依赖 Maven 文案
  • Locality：分类集中
  • 环境错误不改源码

把 warning 集合深化为可执行质量策略 Module

Stronglocal-substitutable

ContractValidationService · PersistenceNodeService · ProjectContract · ProjectStructure · generated pom/package metadata

Before

package ...
No tests
missing Bean
warnings → persist anyway → final compile
质量策略散落在 prompt、regex 与日志判断

After

Deep Quality Policy Module
ProjectProfile: Java / Node / runtime
Gate: source, tests, wiring, contract
Decision: pass / block / needs-review
Adapter: Java 8 Spring template · Java 17 WebSocket template · Node 14 frontend template
Problem

可确定的错误只产生 warning，Interface 没有阻止坏产物进入下一步。

Solution

按 ProjectProfile 执行硬门禁；模板 Adapter 固化工程骨架与运行约束。

Wins
  • Leverage：规则复用全部生成
  • Locality：策略集中
  • LLM 不再猜骨架

Problem

共享状态只保存“最新值”，诊断和回归缺少历史 Locality。

Solution

记录 runId、node、artifact、gate evidence、repair diff 与决策。

Wins
  • 失败可回放
  • 修复效果可比较
  • 界面不解析日志

Top recommendation

先建立垂直切片交付 Module

它把反馈提前，并迫使 VerificationResult、质量策略和正确返工路由在一个真实 Interface 上落地；其余候选都能作为该 Module 的内部 Depth 逐步加入。
